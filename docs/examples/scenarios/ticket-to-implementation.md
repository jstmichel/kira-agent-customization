# Ticket To Implementation Workflow

Use this flow when the request starts from a GitHub issue, Azure work item, or similarly structured ticket.

## Example

1. Resolve the ticket details first.
2. Extract the goal, constraints, acceptance criteria, and linked context.
3. Decide whether the change can go straight to implementation or needs planning.
4. Hand off to build only after the ticket scope is concrete.
5. Validate the changed files and any install or workflow surface that moved.

## Why It Helps

- keeps ticket context from being skipped
- improves alignment with acceptance criteria
- reduces premature implementation on ambiguous requests
